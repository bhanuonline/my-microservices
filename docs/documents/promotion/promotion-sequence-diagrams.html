Diagram 1 — Complete End-to-End Flow (cashback_10 example)

This traces a cashback promotion from the moment a business user creates it, through publishing, cart calculation, Drools evaluation, and the customer seeing the result.

1A. Rule Creation & Publishing (design-time)

What's happening: A business user creates the promotion in Backoffice. When they click "Publish", the system compiles the JSON conditions+actions into Drools DRL code.
sequenceDiagram
    actor BU as Business User
    participant BO as Backoffice UI
    participant PSR as PromotionSourceRule
    participant CT as Condition Translators
    participant AT as CashbackAction Translator
    participant DR as DroolsRule
    participant RBP as RuleBasedPromotion

    rect rgb(232, 240, 248)
    Note over BU,RBP: STEP 1 — Create the Rule
    BU->>BO: Pick template "shukranpay_cashback_promotion"
    BU->>BO: Set conditions: concepts=MAX,SPLASH + categories=women-tops + cart total>=400 AED
    BU->>BO: Set action: cashback=20 AED, expiry=90 days, redeemable=MAX,SPLASH,CENTREPOINT
    BO->>PSR: Save PromotionSourceRule(code="cashback_10")
    Note over PSR: status = UNPUBLISHED
conditions = JSON string
actions = JSON string
    end

    rect rgb(240, 235, 245)
    Note over BU,RBP: STEP 2 — Publish (Compile to Drools)
    BU->>BO: Click "Publish"
    BO->>CT: Compile condition: y_qualifying_categories
    CT-->>BO: Drools IR: ProductRAO.categories CONTAINS "women-tops"
    BO->>CT: Compile condition: lmg_qualifying_concepts
    CT-->>BO: Drools IR: LMGConceptRAO.code IN [MAX, SPLASH]
    BO->>CT: Compile condition: y_cart_total
    CT-->>BO: Drools IR: CartRAO.total >= 400

    BO->>AT: Compile action: y_cashback
    Note over AT: pushConditionParameters():
copies y_cart_total_value=400
into action params
    AT-->>BO: RuleIrExecutableAction → bean "ruleCashbackAction"

    BO->>DR: Create DroolsRule(code="cashback_10", ruleContent=DRL)
    BO->>RBP: Auto-create RuleBasedPromotion(code="cashback_10")
    DR-->>RBP: Link: droolsRule ↔ promotion
    Note over PSR: status = PUBLISHED
    end

1B. Runtime — Cart Calculation to Drools Evaluation

What's happening: A customer adds items to cart. The cart calculation chain triggers promotion evaluation, RAO facts are built, and Drools fires the matching rules.

    participant Cart as CartModel
    participant LCS as LMGCommerce

    participant CS as CalculationService
    participant PES as DefaultPromotion
EngineService
    participant CRES as CommerceRule
EngineService
    participant PRES as LMGPlatformRule
EngineService

    rect rgb(230, 245, 239)
    Note over CU,PRES: STEP 3 — Cart Calculation Triggers
    CU->>Cart: Add 3 MAX items (175 AED each)
    Cart->>LCS: calculateCart(parameter)
    Note over LCS: Check DELAY flag? → No
Check additionalCostOnly? → No
    LCS->>CS: calculate(cartModel)
    Note over CS: Line totals: 3 × 175 = 525 AED
    CS-->>LCS: Cart subtotal = 525 AED
    LCS->>PES: updatePromotions(promoGroups, cart)
    end

    rect rgb(228, 245, 245)

WHERE active=true
AND currentVersion=true

    PRES-->>CRES: Active rules loaded (incl. cashback_10)
    Note over CRES: Create KIE Session
Insert ALL facts
fireAllRules()
    end

    rect rgb(253, 243, 228)
    Note over Cart,DWM: STEP 4 — Build Facts (RAO Population)
    Cart->>CP: expandFactModel(cartModel)

    CP->>CRP: populate(cartModel, cartRAO)
    Note over CRP: Sets: code, currency, total=525
Groups entries by concept
MAX subtotal = 525 AED
→ LMGConceptCartTotalRAO(MAX, 525)
    CRP-->>CP: CartRAO with conceptTotals + paymentInfo

1D. Runtime — Drools Fires → RAO Action → Strategy Persists → Customer Sees

What's happening: Drools matches cashback_10, the RAO action builds a CashbackRAO, the strategy saves it to the database, and the customer sees the result.
sequenceDiagram
    participant DRL as Drools Engine
    participant EA as LMGRuleExecutable
Action (try-catch)
    participant RAO as LMGRuleCashback
RAOAction
    participant Utils as LMGRaoUtils
    participant MAP as promotionAction
StrategiesMapping
    participant STR as LMGCashback
ActionStrategy
    participant DB as Database
    participant SF as Storefront

    rect rgb(253, 234, 234)
    Note over DRL,SF: STEP 5+6 — Drools Fires Rule & RAO Action
    Note over DRL: Rule cashback_10 evaluating:
✓ concept = MAX
✓ category = women-tops
✓ cart total 525 >= 400
ALL CONDITIONS MET → FIRE!
    DRL->>EA: executeAction(context, params)
    Note over EA: try-catch wrapper:
if this fails, other promos continue
    EA->>RAO: performAction(context, params)
    Note over RAO: Read params:
cashback_value=20
y_cart_total_value=400
(pushed by translator!)
    RAO->>Utils: getEligibleCartAmountForCartLevelPromo()
    Utils-->>RAO: eligible = 525 AED
    Note over RAO: 525 >= 400 → threshold met ✓
    Note over RAO: Build LMGCashbackRAO:
value=20, expiry=90 days
redeemable=[MAX,SPLASH,CP]
    RAO-->>DRL: LMGCashbackRAO added to CartRAO.actions
    Note over RAO: Consume 3 order entries
(prevents double-counting)
    end

    rect rgb(248, 234, 243)
    Note over DRL,SF: STEP 7 — Strategy Persists to Database
    DRL-->>MAP: Drools done → process results
    MAP->>MAP: Lookup: defaultRuleLMGCashbackRAOAction
→ defaultCashbackActionStrategy
    MAP->>STR: apply(cashbackRAO)
    STR->>DB: Create PromotionResultModel(certainty=1.0)
    STR->>DB: Create RuleBasedCashbackActionModel
    Note over STR: Serialize to JSON:
{"cashbackValue":20,
"orderThresholdValue":400,
"redeemableConcepts":[...],
"expiryInDays":90}
    STR->>DB: Save: result + action + order
    end

    rect rgb(230, 245, 239)
    Note over DRL,SF: STEP 8 — Customer Sees Result
    SF->>DB: Read order.getPromotionResults()
    DB-->>SF: PromotionResult → cashback_10
    Note over SF: isCashbackPromotion? ✓
Read cashbackAttributesJson
Display: "Get 20 AED cashback!"
    Note over SF: Cart total stays 525 AED
(cashback is informational,
not a discount)
    end

    rect rgb(232, 240, 248)
    Note over BX,DRL: FILE 1 — beans.xml: Define RAO
    Note over BX: Define LMGConceptRAO

    BX-->>POP: Generated: LMGConceptRAO.java

    Note over BX,DRL: FILE 2 — RAO Populator: Fill data

    convertConcept(
      baseProduct.getConcept()))

    end

Diagram 4 — Simplified Overview (Interview Quick-Draw)

A compact version you can sketch on a whiteboard in 2 minutes during an interview.

Interview tip: Draw this on the whiteboard while talking. Start from the left, draw each box, explain as you go. The interviewer will be impressed that you know the exact class names.
sequenceDiagram
    actor BU as Business User
    actor CU as Customer
    participant BO as Backoffice
    participant TRANS as Translators
    participant CART as Cart Calculation
    participant RAO as RAO Providers
+ Populators
    participant DRL as Drools Engine
    participant ACT as RAO Action
    participant STR as Action Strategy
    participant DB as Database
    participant UI as Storefront

    BU->>BO: Create rule (conditions + actions as JSON)
    BO->>TRANS: Publish → compile JSON to Drools DRL
    Note over TRANS: Condition translators → IR conditions
Action translators → IR actions

    CU->>CART: Add item to cart
    CART->>CART: CalculationService (line totals)
    CART->>RAO: updatePromotions()
    RAO->>DRL: Convert cart → RAO facts
(Cart, Products, Concepts, Brands...)

    DRL->>DRL: Insert facts + fire all rules
    DRL->>ACT: Rule matched → execute action
    ACT->>ACT: Build result RAO (e.g. CashbackRAO)
    ACT->>ACT: Consume entries

    ACT-->>STR: promotionActionStrategiesMapping lookup
    STR->>DB: Create PromotionResult + ActionModel
    STR->>DB: Save to database

    UI->>DB: Read PromotionResults
    DB-->>UI: cashback_10 → "Get 20 AED cashback!"
    UI-->>CU: Display promotion message
