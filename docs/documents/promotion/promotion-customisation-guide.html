Promotion Customisation Guide

Where you can customise, how to do it, and real examples from the LMG codebase. Every extension point explained with the exact files to touch.

Section 1 — The Big Picture: 7 Customisation Points

Restaurant analogy: Think of the promotion engine as a restaurant. You can customise: (1) what questions the waiter asks, (2) what dishes the kitchen can cook, (3) what ingredients are available, (4) how the kitchen picks which ingredients to use, (5) when the kitchen starts cooking, (6) how the dish is plated and served, (7) swap out any staff member with your own person.

Section 2 — Add a Custom Condition

WHAT Teach the promotion engine a new question to ask — "Is this customer using a mobile?", "Is this product from the MAX concept?", "Is the card BIN 4532xx?"

The recipe: 6 files to touch

1
beans.xml — Define the RAO class

File: landmarkshopscore/resources/landmarkshopscore-beans.xml

Create a new Java bean class that will carry your custom data into Drools. This is a simple POJO that gets code-generated at build time.

<!-- Example: LMGConceptRAO — carries a concept code into Drools --> <bean class="com.landmarkshops.core.promotionengine.rao.LMGConceptRAO" template="resources/coderao-template.vm"> <property name="code" type="String" equals="true"/> </bean> <!-- If your RAO is a PROPERTY of an existing RAO, extend that RAO too: --> <bean class="de.hybris.platform.ruleengineservices.rao.ProductRAO"> <property name="concept" type="com.landmarkshops.core.promotionengine.rao.LMGConceptRAO" equals="true"/> <property name="brand" type="com.landmarkshops.core.promotionengine.rao.LMGBrandRAO" equals="true"/> </bean>
2
RAO Populator — Fill the RAO with real data

Where: landmarkshopscore/src/.../converters/populator/

Extend an existing populator (or create a new converter) that converts a Hybris model → your RAO.

Two patterns: Pattern A — Extend an OOB populator (most common) Extend the OOB populator, call super.populate(), then add your fields. Example: LMGProductRaoPopulator extends ProductRaoPopulator @Override public void populate(ProductModel source, ProductRAO target) { super.populate(source, target); ← OOB fields ProductModel baseProduct = getBaseProduct(source); target.setConcept(lmgConceptRaoPopulator.convert(baseProduct.getConcept())); ← LMG field target.setBrand(lmgBrandRaoPopulator.convert(baseProduct.getBrand())); ← LMG field } Pattern B — Create a new converter (for entirely new RAO types) Create an AbstractPopulatingConverter that converts Model → RAO. Example: LMGConceptRaoPopulator extends AbstractPopulatingConverter Converts LMGConceptModel → LMGConceptRAO (copies code field)
3
RAO Provider — Insert the RAO into Drools working memory

Where: landmarkshopscore/src/.../rao/provider/

The provider controls which RAO objects become "facts" that Drools rules can match against.

Two patterns: Pattern A — Extend an OOB provider Override expandRAO() to add your custom facts. Example: DefaultLMGCartRAOProvider extends DefaultCartRAOProvider In expandRAO(), adds 3 extra fact-expansion options: • EXPAND_CONCEPT_BRAND → inserts LMGConceptRAO + LMGBrandRAO per product • INCLUDE_CONCEPT_TOTAL → inserts LMGConceptCartTotalRAO per concept • INCLUDE_PAYMENT_INFO → inserts LMGPaymentInfoRAO + LMGCardBinRAOs Pattern B — Create an entirely new provider Implement RAOProvider interface from scratch. Register in orderPromotionRaoProviders. Example: DefaultLMGDeviceRAOProvider implements RAOProvider Creates LMGDeviceRAO from UiExperienceService.getUiExperienceLevel() → Registered as a standalone entry in orderPromotionRaoProviders map
4
Condition Translator — Compile UI params into Drools IR

Where: landmarkshopscore/src/.../definitions/conditions/

The translator converts what the business user configured in Backoffice into Drools intermediate representation (IR) conditions. This IR is then compiled into DRL code.

Your translator implements RuleConditionTranslator with one method: public RuleIrCondition translate(RuleCompilerContext context, RuleConditionData condition, RuleConditionDefinitionData conditionDefinition) Inside translate(), you: 1. Read parameters from condition.getParameters() 2. Generate Drools variables: context.generateVariable(YourRAO.class) 3. Build RuleIr*Condition objects (the "join chain") 4. Return a RuleIrGroupCondition wrapping them all
5
ImpEx Definition — Register in the system

File: landmarkshopsinitialdata/.../essentialData/common/21-essentialdata-definitions.impex

Two inserts needed: 1. The condition definition itself: INSERT_UPDATE RuleConditionDefinition ;id[unique=true] = lmg_qualifying_concepts ;name[lang=$lang] = "LMG Qualifying Concepts" ;priority = 99 ;breadcrumb[lang=$lang]= "Cart {concept_operator} products {concepts}" ;allowsChildren = false ;translatorId = ruleQualifyingConceptsConditionTranslator ← Spring bean alias ;categories(id) = cart 2. The condition parameters: INSERT_UPDATE RuleConditionDefinitionParameter ;definition(id) = lmg_qualifying_concepts ;id[unique=true]= concepts ;type = List(ItemType(LMGConcept)) ← data type for the UI widget ;required = false
6
Spring XML — Wire everything together

File: landmarkshopscore/resources/landmarkshopscore-promotionengine-spring.xml

Three things to wire: A. The translator bean: <alias alias="ruleQualifyingConceptsConditionTranslator" name="defaultRuleQualifyingConceptsConditionTranslator" /> <bean id="defaultRuleQualifyingConceptsConditionTranslator" class="...LMGRuleQualifyingConceptsConditionTranslator" /> B. The condition resolution strategy (adds to lmgConditionResolutionStrategies map): <entry key="lmg_qualifying_concepts" value-ref="conceptConditionResolutionStrategy" /> C. The value mapper (if your parameter uses a custom ItemType): <bean id="lmgConceptRuleParameterValueMapper" class="...LMGConceptRuleParameterValueMapper" /> <bean id="conceptRuleParameterValueMapperDefinition" class="...RuleParameterValueMapperDefinition"> <property name="mapper" ref="lmgConceptRuleParameterValueMapper" /> <property name="type" value="ItemType(LMGConcept)" /> </bean>

Real example: lmg_qualifying_concepts — Full translator code

This is the actual code from the LMG codebase. The translator builds a 4-step join chain: CartRAO → entries → OrderEntryRAO → products → ProductRAO → concept → LMGConceptRAO.code IN [list]

// File: LMGRuleQualifyingConceptsConditionTranslator.java public class LMGRuleQualifyingConceptsConditionTranslator implements RuleConditionTranslator { @Override public RuleIrCondition translate(RuleCompilerContext context, RuleConditionData condition, RuleConditionDefinitionData conditionDefinition) { // 1. Read what the business user selected in Backoffice RuleParameterData conceptsParameter = condition.getParameters().get("concepts"); List concepts = (List) conceptsParameter.getValue(); // 2. Generate unique variable names for the Drools rule String conceptRaoVariable = context.generateVariable(LMGConceptRAO.class); String productRaoVariable = context.generateVariable(ProductRAO.class); String orderEntryRaoVariable = context.generateVariable(OrderEntryRAO.class); String cartRaoVariable = context.generateVariable(CartRAO.class); // 3. Build the join chain (4 conditions ANDed together): // Condition 1: LMGConceptRAO.code IN ["MAX", "SPLASH"] RuleIrAttributeCondition irConceptCondition = new RuleIrAttributeCondition(); irConceptCondition.setVariable(conceptRaoVariable); irConceptCondition.setAttribute("code"); irConceptCondition.setOperator(RuleIrAttributeOperator.IN); irConceptCondition.setValue(concepts); // Condition 2: ProductRAO.concept == $conceptRAO RuleIrAttributeRelCondition irProductConceptRel = new RuleIrAttributeRelCondition(); irProductConceptRel.setVariable(productRaoVariable); irProductConceptRel.setAttribute("concept"); irProductConceptRel.setOperator(RuleIrAttributeOperator.EQUAL); irProductConceptRel.setTargetVariable(conceptRaoVariable); // Condition 3: OrderEntryRAO.products CONTAINS $productRAO RuleIrAttributeRelCondition irOrderEntryProductRel = new RuleIrAttributeRelCondition(); irOrderEntryProductRel.setVariable(orderEntryRaoVariable); irOrderEntryProductRel.setAttribute("products"); irOrderEntryProductRel.setOperator(RuleIrAttributeOperator.CONTAINS); irOrderEntryProductRel.setTargetVariable(productRaoVariable); // Condition 4: CartRAO.entries CONTAINS $orderEntryRAO RuleIrAttributeRelCondition irCartOrderEntryRel = new RuleIrAttributeRelCondition(); irCartOrderEntryRel.setVariable(cartRaoVariable); irCartOrderEntryRel.setAttribute("entries"); irCartOrderEntryRel.setOperator(RuleIrAttributeOperator.CONTAINS); irCartOrderEntryRel.setTargetVariable(orderEntryRaoVariable); // 4. Wrap all in an AND group and return RuleIrGroupCondition group = new RuleIrGroupCondition(); group.setOperator(RuleIrGroupOperator.AND); group.setChildren(Arrays.asList( irConceptCondition, irProductConceptRel, irOrderEntryProductRel, irCartOrderEntryRel )); return group; } }

Section 3 — Add a Custom Action

WHAT Teach the promotion engine a new reward — cashback, free voucher, free shipping, or any custom business logic beyond simple discounts.

Three tiers of action customisation

TIER 1 Fully custom action

New model type + new RAO + new strategy. The most work, but gives you a completely new action type.

LMG examples: Cashback, Voucher, Free Shipping

7 files to touch

TIER 2 Custom RAO action, OOB strategy

New RAO action logic, but reuses an existing strategy (like orderEntryAdjustActionStrategy).

LMG examples: Threshold discounts, BOGO, CCS, Card discounts, RPM

4 files to touch

TIER 3 Override an OOB RAO action

Replace the OOB action bean with your version via Spring alias. Same strategy, same model.

LMG examples: Percentage discount, Fixed discount, Trigger message

2 files to touch

The Tier 1 recipe: 7 files for a fully custom action

3
Action Translator — Compile UI params for Drools

Where: landmarkshopscore/src/.../definitions/action/

DefaultLMGRuleCashbackActionTranslator extends RuleExecutableActionTranslator Key override: pushConditionParameters() Iterates over ALL rule conditions and pushes every condition parameter into the action parameter map. This is how the RAO Action (Step 4) can read condition values like "cart total threshold" at runtime. Without this trick, the action would not know the cart total threshold because Drools actions can only see their own parameters, not conditions.
4
RAO Action — Execute inside Drools

Where: landmarkshopscore/src/.../rule/evaluation/actions/impl/

This runs INSIDE the Drools engine. It creates in-memory RAO objects — no database yet.

DefaultLMGRuleCashbackRAOAction extends AbstractRuleExecutableSupport The performAction() method: 1. Read parameters (cashback_value, is_percentage, threshold from conditions...) 2. Get eligible order entries 3. Calculate eligible cart amount 4. Check if threshold is met 5. Build LMGCashbackRAO with all attributes 6. Add to CartRAO.actions and RuleEngineResultRAO.actions 7. Consume order entries (prevent double-counting)
5

Where: landmarkshopscore/src/.../rule/strategies/

DefaultLMGCashbackActionStrategy extends AbstractRuleActionStrategy<RuleBasedCashbackActionModel> The apply() method: 1. Validate: is it an LMGCashbackRAO applied to CartRAO? 2. Section 5 — Change Entry Selection Strategy

WHAT Control WHICH cart items are consumed by a promotion — the cheapest? the costliest? the most profitable combination?

Analogy: You have a "Buy 2 Get 1 Free" offer. Which item is free? OOB Hybris makes the cheapest one free (DEFAULT). LMG added COSTLIEST (most expensive item free — better for the company) and PROFITABLE (maximizes customer benefit for BOGO).

StrategySourceAlgorithm
DEFAULTOOBNatural order of entries
CHEAPESTOOBSorted ascending by price — cheapest consumed first
COSTLIESTLMG customSorted descending by price — costliest consumed first
PROFITABLELMG customBOGO-aware: sorts descending, alternates between qualifying (X) and free (Y) quantities to maximize free-item value

How to add a new selection strategy

1. Add enum value to OrderEntrySelectionStrategy in items.xml: <value code="MYNEWSTRATEGY" /> 2. Create Java class extending DefaultEntriesSelectionStrategy: Override getOrderEntriesToProcess() with your sorting/selection logic 3. Register in entriesSelectionStrategies map in Spring XML: <entry key="MYNEWSTRATEGY" value-ref="myNewSelectionStrategy" />

Section 8 — Override via Spring Alias

WHAT The master technique — replace ANY out-of-the-box bean with your own via Spring alias. This is how ALL the above customisations are activated.

The pattern:
<alias alias="oobBeanName" name="yourCustomBean" />
<bean id="yourCustomBean" class="YourClass" parent="oobBeanName" />

The alias tells Spring: "whenever someone asks for oobBeanName, give them yourCustomBean instead." The parent inherits the OOB bean's properties so you only override what you need.

Section 9 — Quick-Start Checklists

I want to add a new CONDITION

  1. beans.xml — Define RAO class
  2. Populator .java — Fill RAO from model
  3. Provider .java — Insert RAO into Drools facts
  4. Translator .java — Compile UI params → Drools IR
  5. ImpEx — Register condition + parameters
  6. Spring XML — Wire translator + resolution strategy + value mapper
  7. ant initialize — Load impex into DB
  8. Backoffice — Verify condition appears in rule editor

I want to add a new ACTION (Tier 1)

  1. beans.xml — Define RAO class
  2. items.xml — Define action model type
  3. Translator .java — Compile UI params
  4. RAO Action .java — Execute inside Drools
  5. Strategy .java — Persist to database
  6. ImpEx — Register action + parameters
  7. Spring XML — Wire all 5 beans + 2 maps
  8. ant initialize + ant updatesystem
  9. Backoffice — Verify action appears in rule editor

I want to enrich existing facts

  1. beans.xml — Add property to existing RAO (or new RAO class)
  2. Populator .java — Extend OOB populator, add field in populate()
  3. Spring XML — Alias your populator over the OOB one
  4. If new top-level fact: also update the provider to expand it

I want to override OOB behavior

  1. Find the OOB bean name in the OOB Spring XML
  2. Create your class extending the OOB class
  3. Override the specific method(s) you want to change
  4. Spring XML — <alias alias="oobBean" name="yourBean" />
  5. Set parent="oobBean" to inherit properties
