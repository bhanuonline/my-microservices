Customisation Example 1 — Loyalty Tier-Based Discount

A complete, real-world customisation touching all layers — from business requirement to every file you'd create or modify.

The Business Requirement

"We want to give extra discounts based on the customer's Shukran loyalty tier. Gold members get 5% extra, Platinum members get 10% extra — but ONLY on products from specific brands, and ONLY when shopping from mobile. The discount should show as a separate line 'Loyalty Reward' and we need to track which tier triggered it for analytics."

Breaking down the requirement

Existing asset: The codebase already has LoyaltyTierEnum with values MEMBER, SILVER, GOLD, PLATINUM (used in AbstractOrderLoyaltyInfo and the rewards extension). We'll reuse this enum for our condition.

LMGLoyaltyTierRAOProvider.java — Insert tier fact into Drools

New file: landmarkshopscore/src/.../rao/provider/DefaultLMGLoyaltyTierRAOProvider.java

Pattern copied from: DefaultLMGDeviceRAOProvider — standalone provider (43 lines, simplest pattern)

public class DefaultLMGLoyaltyTierRAOProvider implements RAOProvider { @Resource private LMGLoyaltyService lmgLoyaltyService; @Resource private UserService userService; @Override public Set<?> expandFactModel(final Object modelFact) { // Get current customer final CustomerModel customer = (CustomerModel) userService.getCurrentUser(); // Get tier from loyalty service (already exists in codebase) // LMGLoyaltyService reads tier from Shukran/Epsilon API response final LoyaltyTierEnum tier = lmgLoyaltyService.getCustomerTier(customer); final LMGLoyaltyTierRAO rao = new LMGLoyaltyTierRAO(); if (tier != null) { rao.setCode(tier.getCode()); // "GOLD", "PLATINUM", "SILVER", "MEMBER" } else { rao.setCode("MEMBER"); // default tier } return Collections.singleton(rao); } }
Key decision: We use a standalone provider (like Device) rather than extending the Cart populator, because the tier comes from the customer, not the cart. It's a separate fact — clean and independent.
3
LMGRuleLoyaltyTierConditionTranslator.java — Compile condition

New file: landmarkshopscore/src/.../definitions/conditions/LMGRuleLoyaltyTierConditionTranslator.java

Pattern copied from: LMGRuleDeviceConditionTranslator — simple single-RAO check (no join chain needed)

public class LMGRuleLoyaltyTierConditionTranslator implements RuleConditionTranslator { private static final String TIER_RAO_CODE_ATTRIBUTE = "code"; private static final String PARAM_TIERS = "tiers"; @Override public RuleIrCondition translate(final RuleCompilerContext context, final RuleConditionData condition, final RuleConditionDefinitionData conditionDefinition) throws RuleCompilerException { // 1. Read what business user selected: e.g., [GOLD, PLATINUM] final RuleParameterData tiersParam = condition.getParameters().get(PARAM_TIERS); final List tiers = (List) tiersParam.getValue(); // 2. Generate variable for the LMGLoyaltyTierRAO fact final String tierRaoVar = context.generateVariable(LMGLoyaltyTierRAO.class); // 3. Build condition: LMGLoyaltyTierRAO.code IN ["GOLD", "PLATINUM"] final RuleIrAttributeCondition irTierCondition = new RuleIrAttributeCondition(); irTierCondition.setVariable(tierRaoVar); irTierCondition.setAttribute(TIER_RAO_CODE_ATTRIBUTE); irTierCondition.setOperator(RuleIrAttributeOperator.IN); irTierCondition.setValue(tiers); // 4. Wrap in AND group and return final RuleIrGroupCondition group = new RuleIrGroupCondition(); group.setOperator(RuleIrGroupOperator.AND); group.setChildren(new ArrayList<>()); group.getChildren().add(irTierCondition); return group; } }
Why is this simpler than the concept translator? The concept translator needs a 4-step join chain (Cart → Entry → Product → Concept) because concept lives deep inside products. But tier is a standalone top-level fact — just one direct check. Same pattern as DeviceConditionTranslator.

Why separate fields instead of a JSON blob? For analytics — SQL queries can directly filter by loyaltyTier = 'GOLD' without parsing JSON. The cashback action uses JSON because it has many nested attributes; this one has few fields, so individual columns are better.

LMGRuleLoyaltyDiscountActionTranslator.java — Action translator

New file: landmarkshopscore/src/.../definitions/action/LMGRuleLoyaltyDiscountActionTranslator.java

Pattern copied from: DefaultLMGRuleCashbackActionTranslator — pushes condition params into action

public class LMGRuleLoyaltyDiscountActionTranslator extends RuleExecutableActionTranslator { @Override public RuleIrAction translate(RuleCompilerContext context, RuleActionData action, RuleActionDefinitionData actionDef) { // 1. Call parent to build the standard executable action IR RuleIrAction irAction = super.translate(context, action, actionDef); // 2. Push condition parameters into action parameters // This copies lmg_loyalty_tier_tiers = ["GOLD","PLATINUM"] // into the action params, so the RAO action can read which // tier(s) are configured and set the right percentage pushConditionParameters(context, irAction); return irAction; } private void pushConditionParameters(RuleCompilerContext context, RuleIrAction irAction) { // Same pattern as cashback translator: // iterate all conditions, copy every param into action params // keyed as "{definitionId}_{paramName}" for (RuleConditionData condition : context.getRule().getConditions()) { for (Map.Entry<String, RuleParameterData> param : condition.getParameters().entrySet()) { String key = condition.getDefinitionId() + "_" + param.getKey(); ((RuleIrExecutableAction) irAction).getActionParameters() .put(key, param.getValue().getValue()); } } } }

DefaultLMGRuleLoyaltyDiscountRAOAction.java — Execute inside Drools

New file: landmarkshopscore/src/.../rule/evaluation/actions/impl/DefaultLMGRuleLoyaltyDiscountRAOAction.java

Pattern copied from: DefaultLMGRuleCashbackRAOAction — reads params, checks eligibility, builds RAO

public class DefaultLMGRuleLoyaltyDiscountRAOAction extends AbstractRuleExecutableSupport { @Override public boolean performAction(RuleActionContext context, Map<String, Object> params) { // 1. Read action parameters (set by business user in Backoffice) final BigDecimal goldPercentage = (BigDecimal) params.get("gold_percentage"); final BigDecimal platinumPercentage = (BigDecimal) params.get("platinum_percentage"); final BigDecimal maxDiscount = (BigDecimal) params.get("max_discount_amount"); // 2. Read the customer's ACTUAL tier from condition params // (pushed by translator from lmg_loyalty_tier condition) final List configuredTiers = (List) params.get("lmg_loyalty_tier_tiers"); // 3. Get the customer's actual tier from the Drools facts // (inserted by LMGLoyaltyTierRAOProvider) final LMGLoyaltyTierRAO tierFact = context.getValues(LMGLoyaltyTierRAO.class) .iterator().next(); final String customerTier = tierFact.getCode(); // 4. Determine the discount percentage for this tier BigDecimal percentage = BigDecimal.ZERO; if ("PLATINUM".equals(customerTier)) { percentage = platinumPercentage; } else if ("GOLD".equals(customerTier)) { percentage = goldPercentage; } // SILVER and MEMBER get no loyalty discount if (percentage.compareTo(BigDecimal.ZERO) <= 0) { return false; // no action for this tier } // 5. Calculate the discount amount final CartRAO cartRAO = context.getCartRao(); final BigDecimal cartTotal = cartRAO.getTotal(); BigDecimal discountAmt = cartTotal.multiply(percentage) .divide(BigDecimal.valueOf(100), 2, RoundingMode.HALF_UP); // 6. Apply max cap if (maxDiscount != null && discountAmt.compareTo(maxDiscount) > 0) { discountAmt = maxDiscount; } // 7. Build the LMGLoyaltyDiscountRAO final LMGLoyaltyDiscountRAO discountRAO = new LMGLoyaltyDiscountRAO(); discountRAO.setDiscountPercentage(percentage); discountRAO.setDiscountAmount(discountAmt); discountRAO.setLoyaltyTier(customerTier); discountRAO.setMaxDiscountAmount(maxDiscount); discountRAO.setCurrencyIsoCode(cartRAO.getCurrencyIsoCode()); discountRAO.setAppliedToObject(cartRAO); discountRAO.setFiredRuleCode(context.getRuleName()); // 8. Add to cart and result cartRAO.getActions().add(discountRAO); setRAOMetaData(context, discountRAO); context.insertFact(discountRAO); context.scheduleForUpdate(cartRAO); // 9. Consume order entries consumeOrderEntries(context, cartRAO); return true; } }

public class DefaultLMGLoyaltyDiscountActionStrategy extends AbstractRuleActionStrategy<RuleBasedLoyaltyDiscountActionModel> { @Override public List<PromotionResultModel> apply(AbstractRuleActionRAO action) { if (!(action instanceof LMGLoyaltyDiscountRAO)) { return Collections.emptyList(); } final LMGLoyaltyDiscountRAO discountRAO = (LMGLoyaltyDiscountRAO) action; // 1. Create PromotionResult final PromotionResultModel promoResult = getPromotionActionService().createPromotionResult(action); promoResult.setCertainty(1.0f); // 2. Create the action model final RuleBasedLoyaltyDiscountActionModel actionModel = createPromotionAction(promoResult, action); // 3. Set the tier-specific fields (for analytics!) actionModel.setLoyaltyTier(discountRAO.getLoyaltyTier()); // "GOLD" actionModel.setDiscountPercentage(discountRAO.getDiscountPercentage().doubleValue()); actionModel.setDiscountAmount(discountRAO.getDiscountAmount().doubleValue()); actionModel.setMaxDiscountAmount(discountRAO.getMaxDiscountAmount().doubleValue()); // 4. Create DiscountValue on the order (actual price reduction) final AbstractOrderModel order = getOrderFromCartRAO(discountRAO); final DiscountValue discountValue = new DiscountValue( "loyaltyReward", // discount code discountRAO.getDiscountAmount().doubleValue(), true, // absolute discountRAO.getCurrencyIsoCode() ); addDiscountToOrder(order, discountValue); // shows as "Loyalty Reward" // 5. Save everything getModelService().saveAll(promoResult, actionModel, order); return Collections.singletonList(promoResult); } }
Key difference from cashback: This strategy creates an actual DiscountValue on the order (reduces the cart total). Cashback was informational only. Here, the customer sees a lower price immediately.

How the business user uses it in Backoffice

After deploying all 11 files and running ant initialize + updatesystem: Backoffice → Marketing → Promotion Rules → Create Conditions (IF): ├── lmg_loyalty_tier: tiers = [GOLD, PLATINUM] ├── lmg_qualifying_brands: brands = [NIKE, ADIDAS] ← existing condition, reused └── lmg_qualifying_devices: devices = [Mobile] ← existing condition, reused Action (THEN): └── lmg_loyalty_discount: gold_percentage = 5 platinum_percentage = 10 max_discount_amount = 200 Result: Gold member on mobile buying Nike shoes → 5% off (max 200 AED) labeled "Loyalty Reward" Platinum member on mobile buying Adidas → 10% off (max 200 AED) labeled "Loyalty Reward" Silver member on mobile buying Nike → No discount (tier not in [GOLD, PLATINUM]) Gold member on desktop buying Nike → No discount (device not Mobile)

Runtime trace — what happens when a Gold member adds Nike shoes on mobile

1. Customer (Gold member) adds Nike shoes on mobile → cart calc triggers 2. RAO Providers build facts: CartRAO, OrderEntryRAO, ProductRAO(brand=NIKE) + LMGLoyaltyTierRAO(code="GOLD") ← our new provider + LMGDeviceRAO(code="Mobile") ← existing provider + LMGBrandRAO(code="NIKE") ← existing provider 3. Drools evaluates rule: ✓ LMGLoyaltyTierRAO.code IN [GOLD, PLATINUM] ← GOLD matches ✓ LMGBrandRAO.code IN [NIKE, ADIDAS] ← NIKE matches ✓ LMGDeviceRAO.code IN [Mobile] ← Mobile matches → ALL CONDITIONS MET → FIRE! 4. RAO Action runs: Reads gold_percentage=5, customer tier="GOLD" Cart total = 800 AED → discount = 800 × 5% = 40 AED Builds LMGLoyaltyDiscountRAO(percentage=5, amount=40, tier="GOLD") 5. Strategy persists: Creates PromotionResult + RuleBasedLoyaltyDiscountActionModel Sets loyaltyTier="GOLD", discountPercentage=5.0, discountAmount=40.0 Creates DiscountValue("loyaltyReward", 40 AED) on order 6. Customer sees: Subtotal: 800 AED Loyalty Reward: −40 AED (5% Gold tier discount) Total: 760 AED 7. Analytics team can query: SELECT loyaltyTier, COUNT(*), SUM(discountAmount) FROM RuleBasedLoyaltyDiscountAction GROUP BY loyaltyTier → GOLD: 1,234 orders, 45,000 AED total discount → PLATINUM: 567 orders, 38,000 AED total discount
