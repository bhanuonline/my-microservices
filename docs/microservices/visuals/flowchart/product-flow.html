🛍 Product API — Request Flow

Step 6 of 8 · GET /api/v1/products — same hops as user API, different service

Why this page?

This page shows how the exact same request pattern as the user API routes to a different service. Pay attention to the Eureka lookup step — that's the only thing that differs. The pattern is: gateway handles auth + routing, service handles data.

The point: adding a new business service means configuring the gateway route and registering with Eureka. The hop structure (auth → eureka → proxy → db) is identical for every service.

Try it

# Prereq: nano running + product-service via mvn
make up-nano
make debug-product    # separate terminal

# Hit it:
curl -u admin:admin123 http://localhost:8080/api/v1/products

# Expected: [] (empty — nothing inserted yet)

# Insert something:
curl -u admin:admin123 -X POST http://localhost:8080/api/v1/products \
     -H "Content-Type: application/json" \
     -d '{"name":"Widget","price":29.99,"stock":100}'

# Fetch again — see it:
curl -u admin:admin123 http://localhost:8080/api/v1/products

Common issues

SymptomLikely causeFix
503 Service Unavailable product-service not running or not yet registered with Eureka Check curl http://localhost:8761/eureka/apps | grep PRODUCT. Wait ~30s after boot.
404 on /api/v1/products Gateway route not configured (unlikely — predefined) Check config-repo/api-gateway.yml for route mapping.
500 "Table 'productdb.product' doesn't exist" Hibernate hasn't created tables (fresh nano run) Check product-service logs — ddl-auto=update should create them on first boot.
