📐 Nano Startup Order

Step 4 of 9 — 5 healthcheck-gated waves. ~45-60s on a warm boot, ~5-8 min first boot.

5 waves healthcheck-gated ~45-60s warm

The dependency chain

Docker Compose waits for each wave's healthchecks before starting the next. If any wave fails, downstream waves stay in Created state.

Timing breakdown

WaveServiceTypicalWhat's happening
1mysql-shared~15sMySQL init, create 4 schemas (first boot only)
kafka~10sKRaft broker startup
redis~2sNo persistence init
2eureka-server~15sSpring Boot startup, listens for registrations
3config-server~10sRegisters with Eureka, loads config repo
4auth-server~15sHibernate DDL, Spring Security, OAuth2 endpoints
5api-gateway~10sReactive Netty, pulls routes from Eureka
Total: ~45-60s warm boot. First boot (fresh images): add 5-8 min for Maven dep download + Docker image builds.

What a stuck boot looks like

If a wave never passes its healthcheck, downstream containers stay Created:

docker compose ps
# Look for anything "Created" (not "Up (healthy)")

docker compose logs --tail 30 <stuck-service>
# Common culprits:
#   - port 3306 taken (brew mysql running)
#   - MYSQL_ROOT_PASSWORD missing from .env
#   - Docker Desktop OOM-killed something
Don't restart just the stuck container. If Wave 1 failed, Waves 2-5 are inconsistent. Always make down && make up-nano to recover cleanly.
