"If I stop X, what breaks?"

If this stops… These break immediately These degrade gracefully
mysql-shared All business services, auth-server (can't query users) Gateway stays up (uses Redis + Eureka only)
kafka Order sagas stop progressing. Notifications stop firing. Read APIs (GET /users, GET /products) still work
redis Gateway refuses to start (hard dep) —
eureka-server New service instances can't register. Gateway can't find services. Existing requests complete (gateway caches Eureka state ~30s)
config-server New service starts fail (can't fetch config) Already-running services keep working with cached config
auth-server Gateway returns 401 on every call (can't validate JWT) —
api-gateway All external requests fail (only exposed port) Services keep running internally; can be hit directly on their ports
user-service /api/v1/users endpoints return 503 Everything else works
product-service /api/v1/products + order checkout (stock check fails) User/payment APIs unaffected
order-service Checkout API returns 503. In-flight sagas stall. Browse/user APIs work
payment-service Checkouts stall after order created (saga waits for payment reply) Browse/user APIs work
notification Order status stays at PAID, never reaches NOTIFIED Everything else works

Call types explained

Sync HTTP calls

  • Gateway → business service — request/response, caller waits
  • Gateway → auth-server — JWT validation (cached briefly)
  • order-service → product-service — stock availability check during checkout

Async Kafka events

  • order-service → Kafka → product-service — "reserve stock" command
  • order-service → Kafka → payment-service — "charge payment" command
  • payment-service → Kafka → order-service — "payment succeeded/failed" reply
  • order-service → Kafka → notification — "notify user" event

Infrastructure calls

  • Every service → mysql-shared — JPA/Hibernate queries via HikariCP
  • Every service → eureka-server — register at boot, heartbeat every 30s
  • Every service → config-server — fetch YAML config at boot
  • api-gateway → redis — rate-limit counters, API-key cache, idempotency keys

Reading the diagram during an outage

Example: Your checkout is stuck. The diagram tells you to check: order-service → product-service (sync) and order-service → Kafka → payment-service (async). Use make kafka-group-describe GROUP=order-saga to see if lag is growing.
Example: Gateway says 401 on every call. The diagram points at gateway → auth-server. Check docker compose logs auth-server first.
