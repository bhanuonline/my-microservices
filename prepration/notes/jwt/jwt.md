# JWT Notes -- Level 1: Why Was JWT Created?## Learning GoalUnderstand why JWT was introduced before learning how it works.## What problem existed before JWT?Before JWT, most applications used Session-Based Authentication.### Session Flow1.  User logs in.2.  Server validates credentials.3.  Server creates a session.4.  Session ID is stored on the server.5.  Browser stores the Session ID cookie.6.  Browser sends the Session ID with every request.7.  Server finds the session and identifies the user.**Key Point:** The server remembers the user.## Problems with Sessions-   Hard to scale across multiple servers.-   Requires Sticky Sessions, Redis, or a shared database.-   Consumes server memory.-   Not ideal for microservices.## Why JWT?JWT enables **stateless authentication**. Instead of the serverremembering the user, the **user carries identity** inside a digitallysigned token.## Main Idea-   Session: Server remembers the user.-   JWT: User carries identity.## Advantages-   Stateless-   Highly scalable-   Microservice friendly-   No server-side session storage-   Lower memory usage-   Any server can validate the token## Interview DefinitionJWT (JSON Web Token) is a compact, digitally signed token used forstateless authentication and authorization.## Must Remember-   JWT = JSON Web Token-   Stateless authentication-   Client sends token with every request-   Server validates token-   Suitable for distributed systems-   Improves scalability## Interview AnswerJWT was introduced to implement stateless authentication. Instead ofstoring user sessions on the server, JWT stores user identity inside adigitally signed token. The client sends this token with every request,and the server validates it without maintaining session state. Thismakes applications more scalable and suitable for microservices.
